# 영상 품질 방어와 상위 2개 소재군 운영 설계

## 목표

최근 운영에서 확인된 네 가지 회귀를 차단한다.

1. 우주 소재 등에서 본문 영상이 지나치게 어둡게 합성되는 문제
2. 모델 지시문인 `100자 이하 제목`이 실제 제목에 포함되는 문제
3. Wikimedia의 내부 이미지 파일명이 공개 설명란에 노출되는 문제
4. 제목·본문·CTA 사이에서 음성 크기가 갑자기 달라지는 문제

하루 4회 업로드는 유지하되, 새 미스터리 방향 적용 이후 조회수와 좋아요가 상대적으로 높았던 `science_mystery`와 `hidden_world` 두 소재군을 각각 하루 2회 운영한다.

## 원인

### 어두운 영상

현재 품질 검사는 `blackdetect`로 완전히 검은 프레임의 비율만 측정한다. 별이나 작은 광원이 있는 매우 어두운 영상은 검은 프레임으로 판정되지 않아 통과한다. 실제 우주 영상은 `black_ratio=0`이었지만 상하단을 제외한 본문 영역에서 초 단위 평균 휘도 `YAVG`가 22~35인 구간이 반복됐다.

### 제목 지시문 노출

작가 프롬프트의 JSON 예시에 `"title": "100자 이하 제목"`이 들어 있다. 모델이 이를 값의 일부로 복사해도 현재 계약은 5~100자 길이만 검사하므로 정상 제목으로 승인한다.

### 설명란 파일명 노출

Wikimedia 출처를 공개 설명에 추가할 때 `media_id`를 자료명으로 사용한다. `File:Nan Madol 11.jpg` 같은 내부 식별자가 그대로 사용자에게 노출된다.

### 음량 변화

Google Chirp 3 HD가 생성한 각 MP3의 음량 차이가 있는데, 현재 파이프라인은 무음만 제거한 WAV를 별도 음량 정규화 없이 연결한다. 확인한 영상은 인트로 약 -24.7 LUFS, 후반 약 -17.3 LUFS로 약 7.4 LU 차이가 났다.

## 설계

### 1. 제목 방어

- 작가 프롬프트의 제목 예시를 실제 제목 형태로 바꾼다.
- 스토리 계약에서 다음과 같은 메타 지시문 유출을 거부한다.
  - `100자 이하`
  - `제목:`
  - `글자 수`
  - JSON 필드 안내를 그대로 복사한 표현
- 첫 계약 검증 실패 시 기존 작가 재작성 경로를 한 번 사용한다.
- 재작성도 실패하면 검증된 `topic.topic`을 제목으로 사용하는 기존 안전 템플릿 경로를 사용한다.
- 업로더에서도 같은 지시문 유출 검사를 수행해 오래된 사전 제작본이 업로드되는 것을 막는다.

### 2. 공개 설명 정리

- `produce_log.json`에는 원본 `media_id`를 그대로 보존한다.
- 공개 설명을 조립할 때만 `File:` 접두사와 이미지 확장자를 제거한다.
- 정리한 자료명이 비어 있거나 기술적 식별자뿐이면 `Wikimedia Commons 이미지 자료`로 표시한다.
- 저작자, 라이선스, 원본 URL은 유지하고 같은 URL은 한 번만 표시한다.

### 3. 음성 정규화

- 제목, 각 본문 씬, CTA의 무음 제거가 끝난 WAV마다 동일한 FFmpeg 음량 정규화를 적용한다.
- 기본 목표는 음성 중심 숏츠에 맞춘 `-16 LUFS`, true peak `-1.5 dBTP`로 둔다.
- 정규화는 재인코딩이 필요한 `_retime_audio`보다 먼저 적용하고, 감속이 발생하면 감속 후 한 번 더 peak limiter를 적용한다.
- 최종 검사에 통합 음량과 Loudness Range를 기록한다.
- 최종 LRA가 허용 범위를 넘으면 업로드 품질검사를 실패시켜 급격한 음량 변화가 있는 결과물을 차단한다.
- BGM과 전환 효과음은 나레이션보다 낮은 기존 볼륨을 유지한다.

### 4. 밝기 검사와 보정

- 상단 260px과 하단 330px의 고정 검은 띠를 제외한 본문 영역만 검사한다.
- 초당 한 프레임을 표본으로 `signalstats.YAVG`를 수집한다.
- 연속된 저휘도 구간과 전체 저휘도 비율을 품질 보고서에 기록한다.
- 개별 스톡을 샷으로 만들 때 기준보다 어두우면 다음 후보 미디어를 먼저 선택한다.
- 정확한 대상 자료라 대체할 수 없을 때만 제한된 `eq=brightness/gamma` 보정을 적용한다.
- 보정 후에도 긴 저휘도 구간이 남으면 완성 영상을 업로드하지 않는다.
- 우주라는 이유만으로 밤 장면을 무조건 밝게 만들지 않고, 대상 형체와 배경 정보를 구분할 수 있는 최소 가독성만 확보한다.

### 5. 두 소재군 배치

하루 4회 시간은 그대로 유지한다.

| 시간 | 내부 슬롯 | 소재군 |
|---|---:|---|
| 11시 | 1 | 과학의 경계/미해결 관측 (`science_mystery`) |
| 14시 | 4 | 숨겨진 세계/금지된 구조 (`hidden_world`) |
| 17시 | 2 | 과학의 경계/미해결 관측 (`science_mystery`) |
| 21시 | 3 | 숨겨진 세계/금지된 구조 (`hidden_world`) |

두 소재군 안에서도 최근 14일의 제목 중복 검사는 유지한다. 같은 사건을 표현만 바꿔 반복하지 않는다.

### 6. 분석 분류 수정

- 업로드할 때 `topic.json`의 실제 `category`를 영상 DB에 저장한다.
- 기존 DB에는 하위 호환 방식으로 `category` 열을 추가한다.
- 분석기는 저장된 카테고리를 우선 사용한다.
- 과거 레코드에 카테고리가 없을 때 현재 슬롯 설정으로 소급 분류하지 않는다. 해당 레코드는 `legacy_unclassified`로 분리한다.
- 새 운영 성과는 조회수, 좋아요, 댓글을 영상 수로 정규화해 두 소재군끼리 비교한다.

## 오류 처리

- 제목 메타 지시문이 남으면 작가 단계에서 한 번 재작성하고 안전 템플릿으로 폴백한다.
- 음량 또는 밝기 검사가 실패하면 사전 제작 실패로 처리해 텔레그램 경고를 보낸다.
- 밝기 분석 명령 자체가 실패하면 품질 확인 불가로 간주하며 조용히 통과시키지 않는다.
- 기존 스테이징 영상도 업로드 직전 제목·밝기·음량 검사를 다시 받는다.

## 테스트

다음 회귀 테스트를 먼저 실패시키고 최소 구현으로 통과시킨다.

1. `100자 이하 제목:`이 포함된 스토리 제목 계약 거부
2. 같은 메타 지시문을 업로더가 재차 거부
3. Wikimedia 공개 출처에서 `File:`과 `.jpg/.png` 제거
4. 음성 정규화 FFmpeg 필터와 적용 순서
5. 본문 영역 저휘도 표본의 탐지
6. 짧은 어두운 전환은 허용하고 긴 저휘도 구간은 거부
7. 네 슬롯이 두 소재군으로 2회씩 배치
8. 업로드 시 실제 카테고리 저장
9. 분석기가 현재 슬롯이 아니라 저장된 카테고리를 사용
10. 카테고리가 없는 과거 영상은 `legacy_unclassified`로 분리

실제 외부 TTS, 스톡 API, Veo 호출과 전체 영상 재생성은 이번 회귀 테스트에서 제외한다.

## 배포

- 로컬에서 대상 테스트와 전체 Python 테스트를 실행한다.
- 서버 코드를 백업한 뒤 변경 파일만 배포한다.
- 서버 환경 변수와 인증 파일은 변경하지 않는다.
- 서버에서 대상 테스트를 다시 실행한다.
- 다음 사전 제작 회차부터 새 밝기·음량·제목 검사와 두 소재군 배치를 적용한다.
