# YPP 심사 대비 제작·업로드 보완 설계

## 목표

하루 4회 일정과 현재 제작 구조를 유지하면서 2026-07-27 2회차부터 수익화 심사 위험을 낮춘다. 이미 완성된 1회차 산출물은 수정하거나 재생성하지 않는다.

## 설계

- 업로더는 `produce_log.json`을 근거로 실제 사용된 Vertex Veo 오프닝만 YouTube `status.containsSyntheticMedia=true`로 공개한다.
- Wikimedia 소스는 중복 제거 후 자료명, 저작자, 라이선스, 원본 URL을 설명란에 자동 추가한다. Pexels·Pixabay는 기존 내부 출처 로그를 유지한다.
- 스톡 검색어는 검증된 실제 대상 앵커를 유지하고, 검색 결과의 설명·URL·태그가 검색어 핵심어와 전혀 겹치지 않으면 사용하지 않는다.
- 작가 프롬프트는 검증된 사실 안에서 채널의 해석 한 문장을 요구하고, 소재별로 네 가지 서사 패턴 중 하나를 결정적으로 선택해 동일한 템플릿 인상을 줄인다.
- API 호출 횟수, 하루 4회 cron, TTS, Veo 모델, 기존 1회차 파일은 변경하지 않는다.

## 오류 처리

- `produce_log.json`이 없거나 손상되면 기존 품질 게이트가 업로드를 차단한다.
- 설명란 5,000자 제한 안에서 크레딧을 추가하며, 공간이 부족한 항목은 추가하지 않는다.
- 관련성 필터로 모든 후보가 탈락하면 기존 검은 배경 안전 폴백을 사용하고 품질 로그에 남긴다.

## 검증

- Veo 사용/미사용 업로드 본문의 합성 미디어 표시 여부
- Wikimedia 크레딧 중복 제거 및 설명란 길이 제한
- 무관한 스톡 후보 배제와 관련 후보 유지
- 검증 대상 앵커와 서사 패턴·채널 해석 지침 포함
- 전체 로컬·서버 pytest, 서버 컴파일, dashboard 상태, cron 9개, 2회차 미생성 상태 확인
