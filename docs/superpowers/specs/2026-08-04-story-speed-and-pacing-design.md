# 스토리 음성 속도·정보량·호흡 개선 설계

## 배경

2026년 8월 4일 17시 영상은 본문 313자, 계획 본문 53초였고, 원래 음성을 0.8배로 감속해 최종 58.2초를 만들었다. 이 자동 감속 때문에 음성이 느리게 들렸고, 대본 분량이 적어 정보 전달이 부족했다. 또한 일부 narration에는 문맥 경계를 표시하는 문장부호가 부족해 TTS가 서로 끊어 읽어야 할 구절을 이어 읽었다.

## 목표

- 현재 Chirp 3 HD Kore 여성 음색을 유지한다.
- 제목·본문·CTA 음성을 피치 변화 없이 1.2배로 재생한다.
- 본문 정보량을 늘려 최종 영상이 보통 65~80초가 되게 한다.
- 문맥상 끊어야 할 구간에 쉼표·마침표가 포함된 대본만 통과시킨다.
- 최종 90초 상한, 사실 검증, 자막 싱크, CTA 1회 규칙을 유지한다.

## 음성 처리

Chirp 3 HD는 API의 `speakingRate` 제어를 사용하지 않으므로, 생성된 제목·각 본문 씬·CTA 음성을 정규화한 뒤 FFmpeg `atempo=1.2`로 변환한다. 기존의 “60초 미만이면 0.8~1.0배로 감속” 로직은 제거한다. 변환 후 음성 길이를 다시 측정하고 그 실측값으로 씬 길이와 자막 타이밍을 만든다.

운영값은 `TTS_SPEED=1.2`를 사용하고, 허용 범위 밖이거나 잘못된 값이면 안전 기본값 1.2를 사용한다. 최종 길이가 90초를 넘으면 기존과 동일하게 제작을 중단한다.

## 대본 분량

스토리 작가는 검증된 `topic.json` 사실만 사용해 9~10개 씬, 본문 narration 합계 560~680자를 작성한다. 각 씬은 공백 포함 최대 80자로 제한한다. 목표 계획 본문은 72~84초로 지정하되, 실제 영상 길이는 1.2배 변환 후 음성 실측값으로 결정한다.

분량을 늘릴 때 새로운 사실을 만들거나 같은 의미를 반복하지 않는다. 검증된 사실의 배경, 관측 방법, 수치의 의미, 불확실한 범위와 시청자가 오해하기 쉬운 지점을 풀어 설명한다. 제목 낭독과 CTA는 계속 본문 밖에서 한 번씩만 합성한다.

LLM 응답이 두 번 계약을 통과하지 못하면 검증 사실 템플릿도 같은 씬 수·분량·문장부호 계약을 만족하도록 구성한다. 사실이 부족한 경우 허위 정보를 보태지 않고 기존 사실의 명시적 claim/value 조합을 사용한다.

## 문장 호흡

작가 프롬프트에 다음 낭독 규칙을 추가한다.

- 의미가 끝나는 곳에는 마침표·물음표·느낌표를 사용한다.
- 전환·대조·조건·원인과 결과의 경계에는 쉼표를 사용한다.
- 문장부호 없이 여러 절을 한 문장처럼 이어 쓰지 않는다.
- 각 narration은 반드시 종결 문장부호로 끝낸다.

계약 검증은 narration의 종결 문장부호와 문장부호 사이의 연속 구간 길이를 검사한다. 지나치게 긴 무구두점 구간은 실패시켜 기존 1회 재작성 경로로 보낸다. TTS 단계는 승인된 문장부호를 그대로 읽게 하며 문맥을 추측해 임의로 문장을 바꾸지 않는다.

## 검증 및 배포

- 1.2배 운영값과 잘못된 환경값의 안전 처리를 단위 테스트한다.
- 제목·본문·CTA 모든 음성에 1.2배 변환이 적용되는지 테스트한다.
- 대본 분량·씬 수·문장 종결·긴 무구두점 구간 계약을 테스트한다.
- 작가 프롬프트와 검증 사실 템플릿이 새 계약을 만족하는지 테스트한다.
- 전체 로컬·서버 테스트를 통과한 동일 커밋을 배포한다.
- 서버 `.env`의 `TTS_SPEED=1.2`를 확인하고 대시보드를 재시작한다.
- 별도 샘플 영상이나 수동 제작은 실행하지 않고 다음 예약 제작부터 적용한다.
