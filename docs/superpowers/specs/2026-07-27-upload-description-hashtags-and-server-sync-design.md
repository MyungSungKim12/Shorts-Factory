# 업로드 설명란 해시태그 및 서버·로컬 동기화 설계

## 목표

- 앞으로 업로드하는 영상의 설명란 끝에 해당 소재와 관련된 해시태그를 자동으로 추가한다.
- 서버에서 수동 수정한 자막 줄바꿈 로직을 로컬에 보존한다.
- 서버와 로컬의 설정 차이를 정리하되 비밀정보가 Git에 포함되지 않게 한다.

## 해시태그 생성 방식

별도 AI 호출을 추가하지 않고 `script.json`의 `tags`를 사용한다. 이 태그는 대본 생성 단계에서 주제에 맞게 만들어지므로 업로드 단계에서 다시 모델을 호출할 필요가 없다.

업로더는 다음 규칙으로 설명란을 구성한다.

1. 기존 설명은 유지한다.
2. 태그 앞의 `#`와 공백·해시태그에 쓸 수 없는 문자를 정리한다.
3. 대소문자를 구분하지 않고 중복을 제거한다.
4. 설명에 이미 포함된 해시태그도 다시 추가하지 않는다.
5. 유효한 주제 태그를 최대 5개까지 설명 마지막 줄에 추가한다.
6. 설명 길이 제한을 넘길 태그는 추가하지 않는다.
7. 유효한 태그가 없으면 기존 설명을 그대로 사용한다.

예시:

```text
사하라 사막 한가운데 있는 거대한 원형 지형의 비밀을 살펴봅니다.

#사하라의눈 #리차트구조 #지구미스터리
```

이 변경은 업로드 요청 본문에만 적용하며 `script.json` 원본은 수정하지 않는다. 이미 업로드된 영상 설명도 변경하지 않는다.

## 서버·로컬 소스 병합

서버에는 Git 메타데이터가 없으므로 파일 내용 기준으로 비교한다. 조사 결과 실질적인 서버 전용 변경은 `app/agents/story_producer.py`의 자막 명시적 줄바꿈과 관련 테스트다.

- 약 13자 폭을 기준으로 어절 경계에서 줄을 나눈다.
- 한국어 단어 중간은 자르지 않는다.
- 인트로·본문·마무리 자막에 동일하게 적용한다.
- 기존 `WrapStyle=2` 설정은 유지한다.

서버의 영문 주석, 빈 줄, 운영 중 생성된 `__pycache__`, 임시 재합성 스크립트는 로컬 최신 소스를 덮어쓸 근거로 사용하지 않는다. 의미 있는 서버 변경만 선별 병합한다.

현재 로컬의 미커밋 변경인 `app/agents/producer.py`의 자막 줄바꿈과 `app/agents/uploader.py`의 실제 업로드 날짜 기준 일일 한도 계산도 사용자 변경으로 간주해 보존한다.

## 설정 동기화와 보안

- 서버 `.env`는 로컬 `.env`와 동기화하되 Git 추적 대상에 포함하지 않는다.
- 동기화 전 기존 로컬 `.env`는 저장소 밖 임시 백업 위치에 보관한다.
- `.env.example`에는 실제 토큰이나 API 키를 넣지 않고 필요한 키 이름과 예시값만 유지한다.
- `credentials/`, YouTube OAuth 토큰, Telegram 토큰, API 키는 출력·커밋하지 않는다.
- 서버와 로컬의 실행 설정 키가 달랐던 Vertex/Veo 항목은 현재 소스가 실제 사용하는 `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`, `GOOGLE_GENAI_USE_VERTEXAI`, `VEO_POLL_SEC` 이름을 기준으로 맞춘다.

## 테스트

- 기존 설명 뒤에 주제 해시태그가 최대 5개 추가되는지 확인한다.
- 공백·선행 `#`·특수문자 정제와 중복 제거를 확인한다.
- 이미 설명에 있는 해시태그를 중복 추가하지 않는지 확인한다.
- 태그가 없을 때 설명이 바뀌지 않는지 확인한다.
- 업로드 요청의 `snippet.description`에 최종 설명이 들어가는지 확인한다.
- 서버 자막 수정 테스트와 전체 테스트를 실행한다.

## 배포 및 완료 기준

1. 서버 자막 수정과 테스트를 로컬에 선별 병합한다.
2. 해시태그 기능을 실패 테스트부터 구현한다.
3. 전체 테스트가 통과하면 변경 소스를 서버에 배포한다.
4. 서버에서 소스 구문 검사와 핵심 테스트를 실행한다.
5. 서버·로컬의 대상 소스가 같은지 다시 확인한다.
6. `.env`와 `credentials/`가 Git에 포함되지 않았음을 확인한다.
