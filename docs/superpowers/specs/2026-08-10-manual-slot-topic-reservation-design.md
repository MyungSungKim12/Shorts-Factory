# 회차별 수동 소재 예약·검수 시스템 설계

## 목표

기존 하루 4회 자동 제작·업로드는 그대로 유지하면서, 사용자가 원하는 회차에만 소재를 미리 예약할 수 있게 한다. 수동 소재 회차는 최종 영상까지 제작한 뒤 프론트에서 확인하고 승인된 경우에만 업로드한다. 자동 회차와 수동 회차는 서로 영향을 주지 않는다.

## 핵심 원칙

- 소재 예약이 없는 회차는 기존 자동 파이프라인을 변경 없이 실행한다.
- 소재 예약은 해당 회차 제작 시작 시각 이전에만 신규 등록·수정할 수 있다.
- 제작 시작 시각이 되면 예약을 원자적으로 잠그고 하나의 작업만 실행한다.
- 수동 소재 영상은 품질검사를 통과해도 사용자 승인 전에는 업로드하지 않는다.
- 반려·실패한 수동 회차는 같은 회차 안에서 다른 소재로 다시 제작할 수 있다.
- 예약 시각이 지나도 승인되지 않은 회차는 보류한다. 승인 시각이 업로드 시각 이후라면 승인 직후 업로드한다.
- 수동 소재는 채널 방향 밖의 주제도 허용하되 화면에 경고한다. 사실 검증, 유튜브 정책, 안전성 검사는 예외 없이 적용한다.

## 사용자 흐름

### 1. 회차 선택

프론트의 `회차별 제작 관리` 영역에 오늘과 다음 날의 4개 회차 카드를 표시한다.

- 1회차: 09:00 제작 / 11:00 업로드
- 2회차: 12:00 제작 / 14:00 업로드
- 3회차: 15:00 제작 / 17:00 업로드
- 4회차: 19:00 제작 / 21:00 업로드

각 카드에는 자동/수동 모드, 소재, 제작·업로드 시각, 현재 상태, 남은 입력 가능 시간을 표시한다.

### 2. 소재 입력과 사전 확인

필수 입력은 자유 형식 소재 한 개다. 선택 입력으로 강조점, 반드시 포함할 내용, 제외할 내용, 참고 링크를 받는다.

한 단어처럼 의미가 모호한 입력은 바로 예약하지 않는다. `소재 확인` 단계에서 가능한 해석 후보를 보여주고 사용자가 하나를 선택하게 한다. 예를 들어 `단종`은 조선의 단종인지, 단종된 제품인지 확인한다.

소재 확인 결과는 다음을 화면에 표시한다.

- 정규화된 소재 제목과 핵심 질문
- 채널 방향 적합 여부와 경고
- 사실 검증 가능 여부와 예상 검증 경로
- 실제 사진·영상 후보 수
- Wikimedia/무료 스톡/기존 AI 자산/신규 AI 오프닝 사용 가능 여부
- 예상 시각 자료 적합도: 높음/보통/부족

검증이나 시각 자료 확보 가능성이 너무 낮으면 예약을 막고 소재 구체화 또는 다른 소재 선택을 안내한다. 사용자가 명시적으로 허용하면 관련 자료 또는 AI 오프닝을 활용할 수 있지만, 대상과 무관한 영상으로 억지 제작하지 않는다.

### 3. 예약과 제작 잠금

사전 확인을 통과한 소재만 해당 회차에 예약할 수 있다. 제작 시각 전에는 수정·취소할 수 있다. 제작 시각이 되면 예약 상태를 `locked`로 바꾸고 입력 버튼을 비활성화한다.

잠금은 SQLite 트랜잭션과 기존 전역 파이프라인 잠금을 함께 사용한다. 같은 회차에 두 영상이 동시에 생성될 수 없다.

### 4. 제작과 실시간 상태

수동 소재는 기존 에이전트 계약을 사용해 다음 순서로 처리한다.

`사실 검증 → 대본 작성 → TTS → 미디어 수집/AI 오프닝 → 합성 → 품질검사 → 검수 대기`

프론트는 2초 간격 상태·로그 폴링으로 현재 단계를 갱신한다. 별도 인프라 없이 기존 FastAPI와 Vercel 프록시 환경에서 안정적으로 동작하도록 SSE 대신 폴링을 사용한다.

화면에는 다음을 표시한다.

- 전체 진행 상태와 현재 단계
- 단계별 시작·종료 시각과 소요 시간
- 최근 로그, 경고, 실패 원인
- 소재 검증 방식과 출처 요약
- 미디어 공급자와 AI 자산 사용 여부
- Telegram 알림과 동일한 주요 성공·실패 이벤트

로그 API는 토큰, API 키, 로컬 자격증명 경로와 외부 응답 원문을 노출하지 않고 허용된 메시지만 반환한다.

### 5. 미리보기와 승인

품질검사를 통과하면 카드가 `검수 대기` 상태가 된다. 프론트에서 다음 항목을 실제로 확인할 수 있다.

- 최종 MP4 영상 재생
- 제목, 대본, 설명, 해시태그
- 영상 길이·해상도·음량·어두운 장면 검사 결과
- 사용한 실제 자료와 AI 자료 구분

영상은 관리 토큰을 포함한 API 요청으로 내려받아 브라우저 Blob URL로 재생한다. 서버 파일 경로를 공개하지 않는다.

`승인` 시 업로드 시각 전이면 예약 업로드 대기 상태가 되고, 업로드 시각 이후면 즉시 단일 업로드 작업을 실행한다.

`반려` 시 반려 사유를 선택 또는 입력한다. 완성물은 복구 가능한 폐기 보관소로 이동하고 같은 회차에 한해 새 소재 입력을 다시 허용한다. 이전 작업이 종료되고 잠금이 해제된 뒤에만 재제작할 수 있다.

## 실패와 재시도

실패 카드에는 실패 단계, 사용자용 원인, 마지막 로그 시각을 표시한다.

제공 기능:

- `같은 소재로 재시도`: 일시적인 API·네트워크·미디어 오류에 사용
- `다른 소재로 재제작`: 기존 결과를 폐기 보관하고 소재 확인부터 다시 시작
- `자동 모드로 전환`: 제작 시작 전까지만 허용하며 해당 회차를 기존 자동 로직에 반환
- `이번 회차 건너뛰기`: 업로드 없이 종료

재시도는 항상 기존 작업 종료와 잠금 해제를 확인한 뒤 하나만 생성한다. 실패한 수동 회차 때문에 다른 회차의 자동 제작이 중단되지 않도록 회차 상태를 분리한다.

## 상태 모델

수동 회차 상태는 다음 상태 중 하나만 가진다.

`draft → checking → reservable → reserved → locked → researching → writing → producing → quality_check → review_ready → approved → uploading → uploaded`

예외 상태:

- `needs_input`: 모호한 소재 또는 자료 부족
- `failed`: 단계 실패
- `rejected`: 사용자 반려
- `held`: 업로드 시각이 지났지만 미승인
- `cancelled`: 제작 전 취소
- `skipped`: 이번 회차 건너뛰기

상태 전이는 백엔드에서만 검증한다. 프론트는 허용된 버튼만 표시한다.

## 데이터 저장

기존 `videos.sqlite`에 두 테이블을 추가한다.

### `slot_reservations`

- `run_id`: `YYYYMMDD-1` 형식의 회차 ID, 기본키
- `mode`: `auto` 또는 `manual`
- 원본 입력과 정규화 소재
- 포함·제외 조건과 참고 링크
- 상태, 현재 단계, 시도 횟수
- 제작·업로드 예정 시각
- 잠금 시각과 소유 작업 ID
- 승인·반려 정보
- 결과 작업 폴더와 video_id
- 생성·수정 시각

### `slot_events`

- 회차 ID와 증가형 이벤트 ID
- 단계, 수준, 사용자용 메시지
- 구조화된 허용 메타데이터
- 생성 시각

이벤트 테이블을 기반으로 페이지 새로고침 후에도 진행 로그를 복원한다.

## API 설계

모든 변경 API는 기존 `DASHBOARD_TOKEN`을 요구한다.

- `GET /api/slots?date=YYYY-MM-DD`: 회차 카드와 현재 상태
- `POST /api/slots/{run_id}/check-topic`: 소재 해석·검증·미디어 사전검사
- `PUT /api/slots/{run_id}/reservation`: 확인된 소재 예약 또는 수정
- `DELETE /api/slots/{run_id}/reservation`: 제작 전 예약 취소
- `GET /api/slots/{run_id}`: 상세 상태와 결과 메타데이터
- `GET /api/slots/{run_id}/events?after_id=N`: 증분 실시간 로그
- `GET /api/slots/{run_id}/video`: 인증된 최종 영상 다운로드
- `POST /api/slots/{run_id}/approve`: 승인 및 예약/즉시 업로드
- `POST /api/slots/{run_id}/reject`: 반려와 폐기 보관
- `POST /api/slots/{run_id}/retry`: 같은 소재 또는 새 소재 재시도
- `POST /api/slots/{run_id}/skip`: 수동 회차 건너뛰기

## 기존 자동 파이프라인과의 결합

스케줄러는 리서처를 실행하기 직전에 해당 `run_id`의 예약을 조회한다.

- 유효한 수동 예약 없음: 현재 자동 로직을 그대로 실행한다.
- `reserved` 수동 예약 있음: 원자적으로 잠근 뒤 입력 소재를 검증하고 수동 제작한다.
- 수동 영상 `approved`: 기존 업로드 시각에 업로드한다.
- `review_ready`, `rejected`, `failed`, `held`: 자동 영상으로 대체하지 않고 해당 회차만 보류한다.

자동 경로의 함수와 파일 계약은 바꾸지 않고, 실행 시작점에 `auto/manual` 결정을 담당하는 작은 해석 계층만 추가한다.

## 프론트 구성

기존 모니터링 대시보드 상단에 `회차별 제작 관리`를 추가한다.

각 회차 카드는 다음 요소를 가진다.

- 자동/수동 배지와 상태 색상
- 제작·업로드 시각, 입력 마감 카운트다운
- 예약 소재와 채널 방향 경고
- 소재 입력/확인/예약/수정 버튼
- 단계 진행 바와 최근 로그 3줄
- 상세 로그 펼치기
- 최종 영상 미리보기와 메타데이터
- 승인, 반려, 같은 소재 재시도, 다른 소재로 재제작 버튼

화면은 모바일에서도 회차별 카드가 한 열로 표시되며, 위험 동작은 확인 창을 거친다.

## 보관과 정리

- 승인 영상은 기존 운영 정책에 따라 관리한다.
- 반려·실패 영상은 별도 폐기 보관소에서 7일 후 삭제한다.
- 재사용 가능한 AI 자산 라이브러리는 기존 정책대로 기간 제한 없이 유지한다.
- 예약·이벤트 이력은 모니터링과 장애 분석을 위해 유지하되 로그 메시지 크기를 제한한다.

## 테스트와 검증

### 백엔드

- 예약 유무에 따른 자동/수동 분기
- 제작 시각 경계와 원자적 잠금
- 중복 제작·중복 업로드 차단
- 승인 전 업로드 차단과 시각 경과 후 즉시 업로드
- 반려·실패·재시도 상태 전이
- 모호한 소재와 미디어 부족 처리
- 자동 회차 회귀 테스트
- 로그 비밀정보 제거

### 프론트

- 회차별 버튼 활성화 조건
- 입력 마감 카운트다운
- 상태 폴링과 증분 로그
- 영상 Blob 미리보기
- 승인·반려·재시도 오류 처리
- 모바일 카드 레이아웃

### 운영 검증

- 수동 회차 하나와 자동 회차 하나를 함께 실행해 서로 간섭하지 않는지 확인한다.
- 승인 전 업로드가 발생하지 않는지 확인한다.
- 자동 회차 4건의 기존 스케줄이 수동 예약이 없을 때 그대로 동작하는지 확인한다.
