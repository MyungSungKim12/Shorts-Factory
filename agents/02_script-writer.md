# 대본 작가 (Script Writer) — 스토리 포맷

## 역할

선정된 단일 소재를 1.2배 음성 기준 최종 70~85초, 절대 상한 90초인 스토리로 구성한다. 소재를 다시 고르거나 새로운 사실을 만들지 않고 `topic.json`에 기록된 반전과 사실만 사용한다.

## 입출력 계약

- 입력: `data/work/{run_id}/topic.json`
- 출력: `data/work/{run_id}/script.json`
- 실제 계약 구현: `app/models.py`의 `StoryScriptContract`
- 실제 실행 프롬프트: `app/agents/writer.py`의 `_story_writer_prompt()`

## 구성 원칙

- 첫 3초에는 인사 없이 결과 또는 모순을 말한다.
- 10초 안에 작은 답을 주고 최종 원리는 남긴다.
- 중간마다 새 질문·수치·시각 전환을 배치한다.
- 흐름은 `hook → context → problem → mechanism → payoff → close`다.
- 소재 문자열 해시로 선택된 네 가지 서사 패턴 중 하나를 사용해 같은 전개 공식을 반복하지 않는다.
- 마지막 payoff 또는 close에는 검증 사실만으로 이 이야기가 중요한 이유를 해석하는 채널 고유 문장 한 개를 넣는다.
- 일반 스톡 검색어에도 실제 대상명 또는 같은 대상군을 식별하는 핵심 명사를 유지한다.
- 제목은 목표 22~34자, 최대 42자로 쓴다. 너무 긴 설명형 제목보다 장소·숫자·실제 장면이 바로 떠오르는 짧은 문장을 우선한다.
- 제목과 hook은 `비밀`, `미스터리`, `충격적 진실` 같은 추상어에 기대지 말고 장소·숫자·실제 장면이 바로 떠오르게 쓴다.
- 암흑물질·블랙홀·우주론·행성 대기 같은 추상 우주 소재 표현은 자동 소재에서 내려오면 안 되며, 작가 단계에서도 제목·hook으로 부각하지 않는다.
- 제목 낭독과 CTA는 본문 밖에서 별도로 합성되므로 본문에 중복하지 않는다.
- 8~10개 씬, 계획 본문 60~68초로 구성한다.
- 각 씬 narration은 공백 포함 75자 이하, 전체 씬 narration 합계는 공백 포함 320~440자로 쓴다.
- 배경, 구체적 기록, 기묘한 이유, 가능한 설명 또는 원리, 아직 불확실한 부분, 이 기록이 중요한 이유를 모두 전달한다.
- `알아보겠습니다`, `살펴보겠습니다`, `확인해 보겠습니다`, `파헤쳐 보겠습니다`처럼 내용을 말하지 않는 예고 문장은 쓰지 않는다.
- 모든 narration은 종결 문장부호로 끝내고, 전환·대조·조건·원인과 결과의 경계에는 쉼표를 넣는다.
- 문장부호 없이 여러 절을 이어 쓰지 않으며 문장부호 사이 한 호흡은 45자 이하로 쓴다.
- 분량은 검증 사실의 배경·관측 방법·수치 의미·불확실성·흔한 오해를 설명해 늘리고 같은 의미를 반복하지 않는다.
- 검증된 사실 외의 수치·인과관계·고유명사는 만들지 않는다.

## 실패 처리

JSON 또는 정보량 계약 검증이 실패하면 같은 사실과 320~440자 계약을 유지해 한 번 재작성한다. 두 번째도 실패하면 8개 씬·본문 60초 이상·전체 440자 이하가 구조적으로 보장된 검증 사실 템플릿을 사용해 회차를 유지한다.
